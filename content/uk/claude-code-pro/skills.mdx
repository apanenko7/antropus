<TLDR>
- <Term id="skill" /> — папка з файлом `SKILL.md`: інструкція для повторюваного процесу, яку агент підвантажує, коли задача підходить, або ти запускаєш через `/назва`.
- Claude завжди бачить лише короткий `description`, а повний текст читає за потреби. Це <Term id="progressive-disclosure" />: багато skills майже не займають контексту.
- <Term id="claude-md" /> — для фактів, які потрібні завжди. Skill — для процедур, які потрібні іноді.
</TLDR>

## Що таке skill

Ти втретє пояснюєш агенту, як у вас пишуться релізні нотатки чи робиться рев'ю? Це кандидат у skill. Ти описуєш процес **один раз** у файлі, і далі агент виконує його однаково щоразу.

Skill — це папка, де головне — файл `SKILL.md`:

```text
.claude/skills/release-notes/
├── SKILL.md        обов'язковий: інструкція
├── template.md     шаблон, який читається за потреби
└── scripts/
    └── collect.sh  скрипт, який агент запускає, а не читає
```

## Анатомія SKILL.md

Згори — <Term id="frontmatter" /> між рядками `---`, далі звичайний markdown з інструкцією:

```markdown
---
name: release-notes
description: Write release notes from git history since the last tag. Use when preparing a release.
disable-model-invocation: true
---

1. Find the last tag: git describe --tags --abbrev=0
2. Read commits since it and group them: Нове / Виправлено / Інше
3. Write in Ukrainian, max 10 bullets
```

| Поле | Навіщо |
| --- | --- |
| `name` | Ім'я команди в меню `/`. Якщо не вказати, береться назва папки |
| `description` | Що робить і **коли** застосовувати. За ним Claude вирішує, чи підвантажити skill |
| `disable-model-invocation: true` | Запускаєш лише ти, сам Claude не викличе. Для дій з наслідками: деплой, коміт |
| `allowed-tools` | Інструменти, які можна без запиту дозволу під час цього запуску |
| `argument-hint` | Підказка аргументу в автодоповненні, наприклад `[issue-number]` |

<Callout type="tip" title="Description — найважливіший рядок">
Claude бачить описи всіх skills і за ними вирішує, що підвантажити. Пиши не лише «що робить», а й «коли застосовувати»: «Use when preparing a release».
</Callout>

## Де лежать і як запускаються

| Де | Шлях | Для кого |
| --- | --- | --- |
| Проєкт | `.claude/skills/<name>/SKILL.md` | Уся команда (комітиться в репозиторій) |
| Особисто | `~/.claude/skills/<name>/SKILL.md` | Ти, у всіх проєктах |
| Плагін | `<plugin>/skills/<name>/SKILL.md` | Хто встановив <Term id="plugin" />; виклик `/plugin-name:skill-name` |

Запустити можна двома способами:

- **Автоматично:** ти просиш «підготуй реліз», Claude бачить відповідний `description` і сам підвантажує skill.
- **Вручну:** `/release-notes`. Аргументи доступні в тексті як `$ARGUMENTS` або `$0`, `$1`…

Старі файли в `.claude/commands/` теж працюють як slash-команди, але для нового краще skills: вони підтримують додаткові файли.
