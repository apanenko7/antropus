<TLDR>
- <Term id="hook" /> — команда, яку Claude Code запускає **сам** на подію: перед викликом інструменту, після редагування, на старті сесії, коли агент закінчив.
- Це детермінізм: інструкція в CLAUDE.md — прохання, яке модель може забути, а хук спрацьовує завжди.
- Налаштовуються в <Term id="settings-json" />: подія → <Term id="matcher" /> → команда. Exit code `2` у `PreToolUse` блокує дію.
</TLDR>

## Прохання проти гарантії

«Після кожної правки запускай prettier» у CLAUDE.md спрацює… майже завжди. Хук `PostToolUse` спрацює **завжди**, бо його запускає Claude Code, а не модель. Тому все, що мусить відбуватися без винятків (форматування, заборони, сповіщення), виноси в хуки.

## Основні події

| Подія | Коли | Типове використання |
| --- | --- | --- |
| `PreToolUse` | Перед викликом інструменту | Заблокувати небезпечну команду |
| `PostToolUse` | Після успішного виклику | Форматер, лінтер, логування |
| `UserPromptSubmit` | Коли ти надіслав повідомлення | Додати контекст, перевірити запит |
| `SessionStart` | Старт або відновлення сесії | Підвантажити стан проєкту |
| `Stop` | Агент закінчив відповідь | Сповіщення, фінальна перевірка |
| `Notification` | Claude чекає на тебе | Звук чи desktop-сповіщення |

Подій більше (про субагентів, стиснення контексту, зміну файлів), повний список — у документації hooks.

## Як виглядає налаштування

Три рівні вкладення: **подія → група з matcher → обробники**. Ось офіційний приклад: prettier після кожного редагування, у `.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "f=$(jq -r '.tool_input.file_path') && npx prettier --write --ignore-unknown \"$f\""
          }
        ]
      }
    ]
  }
}
```

- **matcher** фільтрує за назвою інструменту: `Edit|Write` — лише редагування, `Bash` — лише команди, `*` або порожньо — усе.
- Команда отримує на **stdin** JSON із подією: `tool_name`, `tool_input` (там шлях файлу чи текст команди) тощо. Тому в прикладі `jq` дістає `.tool_input.file_path`.
- Окрім `command`, бувають типи `http`, `prompt` і `agent`: для рішень, де потрібне судження моделі.

## Блокування: exit codes

| Код виходу | Що станеться |
| --- | --- |
| `0` | Успіх, дія продовжується |
| `2` | **Блокування** (на подіях, що вміють блокувати): дію зупинено, текст зі stderr іде агенту як причина |
| Інший (напр. `1`) | Помилка хука, але дія **продовжується** |

<Callout type="warn" title="exit 1 не блокує">
Найчастіша помилка: скрипт-охоронець виходить з кодом 1 і думаєш, що команду заборонено. Ні: блокує тільки `2`. Або exit 0 з JSON, де `permissionDecision: "deny"`.
</Callout>

Перевірити, що налаштовано, можна командою `/hooks`: вона показує всі хуки й файл, звідки кожен прийшов.

<Callout type="pro" title="Хуки виконуються від твого імені">
Хук — це звичайна shell-команда з твоїми правами. Не копіюй чужі хуки, не прочитавши, що вони роблять.
</Callout>
