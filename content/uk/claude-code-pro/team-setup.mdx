<TLDR>
- Налаштування Claude Code живуть у кількох файлах <Term id="settings-json" />. Старший рівень перебиває молодший: **managed → командний рядок → local → project → user**.
- Командне — у `.claude/settings.json` (комітиш), особисте для проєкту — у `.claude/settings.local.json` (не комітиш).
- Набір skills, субагентів, хуків і MCP команда роздає одним <Term id="plugin">плагіном</Term> зі свого <Term id="marketplace">маркетплейсу</Term>.
</TLDR>

## Хто що налаштовує

| Рівень | Файл | Для кого |
| --- | --- | --- |
| User | `~/.claude/settings.json` | Ти, у всіх проєктах: модель, тема, особисті дозволи |
| Project | `.claude/settings.json` | Уся команда (файл у git): дозволи, хуки, плагіни, env |
| Local | `.claude/settings.local.json` | Ти, лише в цьому проєкті; у git не потрапляє |
| Managed | `managed-settings.json` чи політика з адмінки | Уся організація; перебити не можна |

Коли той самий ключ задано в кількох місцях, перемагає старший рівень: <Term id="managed-settings" /> → `--settings` у командному рядку → local → project → user. А от **списки** (наприклад `permissions.allow`) не перебиваються, а **зливаються**: кожен файл додає свої правила.

<Callout type="tip" title="«Yes, and don't ask again» пише в local">
Коли на запит дозволу обираєш «не питати знову», Claude Code зберігає правило в `.claude/settings.local.json`. Тож твої особисті дозволи не потрапляють у командний файл.
</Callout>

## Правила дозволів

Кожне правило — це інструмент і що йому можна:

```json
{
  "permissions": {
    "allow": ["Bash(npm run *)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]
  }
}
```

- **allow** — без запиту. **ask** — завжди питати. **deny** — заборонено.
- Перевіряються в порядку **deny → ask → allow**: заборона сильніша за дозвіл.
- `deny` і `ask` з командного файлу діють одразу, а `allow` — лише після того, як людина **довірилася** папці (питання «Do you trust the files in this folder?»). Так чужий репозиторій не видасть собі прав сам.

<Callout type="warn" title="Правило збігається з тим, як написано">
`Bash(git push *)` не зловить `git -C . push`, а `Read(./.env)` не зупинить `grep -r` по всій папці. Для справжньої ізоляції є блок `sandbox` у налаштуваннях: про нього в модулі «Агентне середовище».
</Callout>

## Плагіни для команди

Плагін — це папка з маніфестом `.claude-plugin/plugin.json`, у якій можуть бути skills, субагенти, хуки й MCP-сервери. Ставиться одним пакетом через `/plugin`. Маркетплейс — каталог плагінів (репозиторій із `marketplace.json`).

Щоб у кожного, хто клонує репозиторій, був ваш маркетплейс і потрібний плагін, додай у командний `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "acme-tools": {
      "source": { "source": "github", "repo": "acme-corp/claude-plugins" }
    }
  },
  "enabledPlugins": {
    "code-formatter@acme-tools": true
  }
}
```

Перевірити, які файли налаштувань реально завантажилися, можна командою `/status` (рядок `Setting sources`).
