<TLDR>
- Модель обирає й використовує інструмент майже лише за його назвою, описом і схемою параметрів. Пиши їх як інструкцію новому колезі.
- Менше, але розумніших інструментів: не обгортай кожен ендпоінт API, а роби інструменти під реальні задачі.
- Відповіді інструментів мають бути короткими й зрозумілими, а помилки — підказувати, як виправити.
</TLDR>

## З чого складається інструмент

<Term id="tool-definition">Опис інструмента</Term> для Claude — це JSON з трьох основних частин:

```json
{
  "name": "orders_search",
  "description": "Шукає замовлення клієнта за email або номером замовлення. Використовуй, коли користувач питає про статус, вміст чи дату замовлення. Повертає до 10 останніх замовлень.",
  "input_schema": {
    "type": "object",
    "properties": {
      "customer_email": { "type": "string", "description": "Email клієнта, напр. olena@example.com" },
      "order_id": { "type": "string", "description": "Номер замовлення у форматі ORD-12345" }
    },
    "required": []
  }
}
```

- **name** — коротка, однозначна назва дії;
- **description** — що робить, **коли** використовувати, що повертає, обмеження;
- <Term id="input-schema" /> — параметри з типами й поясненнями. Можна додати `strict: true`, щоб параметри гарантовано відповідали схемі.

Усе це разом — <Term id="aci" />: інтерфейс, через який агент «бачить» світ. Вкладай у нього стільки ж уваги, скільки в UI для людей.

## Ще кілька правил

- **<Term id="tool-namespacing">Простори імен</Term>.** Коли інструментів багато, групуй префіксами: `asana_search`, `jira_search`. Агент менше плутає схожі дії.
- **Ощадливість до токенів.** Пагінація, фільтри, обрізання з розумними значеннями за замовчуванням. Можна дати параметр `response_format` зі значеннями `concise` / `detailed`. Claude Code за замовчуванням обмежує відповідь інструмента 25 000 токенів.
- **Захист від помилок.** Проєктуй так, щоб помилитися було важче: наприклад, вимагати абсолютні шляхи до файлів, а не відносні.
- **Тестуй.** Прожени агента на реалістичних задачах, читай його міркування й виклики, покращуй описи. Claude може сам проаналізувати такі логи й запропонувати правки.
