<TLDR>
- <Term id="mcp" /> — стандартний «роз'єм»: пишеш сервер один раз, і ним користуються Claude Code, Claude Desktop, IDE та інші <Term id="mcp-host">хости</Term>.
- Сервер дає три речі: **tools** (дії), **resources** (дані для контексту), **prompts** (готові шаблони).
- Локально — транспорт <Term id="stdio" />, для віддаленого сервісу — <Term id="streamable-http" /> з авторизацією (рекомендовано OAuth).
</TLDR>

## Хто є хто

**Аналогія:** USB. Ноутбук (хост) не знає, що за пристрій ти вставив, але завдяки стандарту з ним працює.

- **Хост** — AI-застосунок: Claude Code, Claude Desktop, VS Code.
- **Клієнт** — з'єднання всередині хоста; на кожен сервер окремий клієнт.
- **Сервер** — твоя програма, що надає контекст і дії. Може працювати локально або в хмарі.

Сервер не знає, яка модель ним користується: про модель дбає хост.

## Tools, resources, prompts

<Demo script={mcpDesignDemo} />

| Примітив | Що це | Приклад для сервера бази магазину |
| --- | --- | --- |
| **Tools** | Дії, які модель може викликати | `orders_query` — запит замовлень з фільтрами |
| **Resources** | Дані для читання, контекст | Схема бази `schema://orders` |
| **Prompts** | Шаблони взаємодії, які обирає користувач | «Тижневий звіт продажів» з прикладами запитів |

Хост дізнається про можливості сервера через запити на кшталт `tools/list`, а викликає інструмент через `tools/call`. Повідомлення ходять у форматі JSON-RPC 2.0. Більшість цього бере на себе SDK, тож вручну протокол писати не треба.

<Callout type="tip" title="Все з уроку про інструменти діє і тут">
<Term id="mcp-resource">Ресурси</Term> і <Term id="mcp-prompt">промпти</Term> — додаткові можливості, але більшість цінності сервера зазвичай в інструментах. Тож правила з попереднього уроку (назви, описи, короткі відповіді, корисні помилки) — головне в дизайні MCP-сервера.
</Callout>

## Транспорт і доступ

| | stdio | Streamable HTTP |
| --- | --- | --- |
| Де працює | Локально, на тій самій машині | Віддалено, по мережі |
| Скільки клієнтів | Зазвичай один | Багато |
| Авторизація | Не потрібна мережева | Bearer-токени, API-ключі; рекомендовано OAuth |
| Приклад | Сервер файлової системи | Хмарний сервіс на зразок Sentry |
