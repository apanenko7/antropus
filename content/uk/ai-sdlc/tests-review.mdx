<TLDR>
- Агент зупиняється, коли робота **виглядає** готовою. Дай йому перевірку, яку він може запустити сам: тести, typecheck, lint, скріншот.
- Рев'ю роби тим, хто не писав код: свіжою сесією, `/code-review` або субагентом-рев'юером, що лише читає.
- Обов'язкові перевірки — у <Term id="quality-gate">ворота</Term>: хуки й <Term id="ci" />, а не «будь ласка» в промпті.
</TLDR>

## Дай агенту ціль, яку можна перевірити

Без перевірки тестувальником стаєш ти: кожна помилка чекає, поки ти її випадково помітиш. Найкращі цілі для агента:

## Тести першими

<Term id="tdd" /> з агентом працює особливо добре, бо тест — це ціль, яку він бачить:

1. «Напиши тест, що відтворює баг» → тест **червоний** (баг підтверджено).
2. «Виправ» → тест **зелений**.
3. Повний прогін тестів, щоб не було <Term id="regression">регресій</Term>.

<Callout type="warn" title="Тести не можна «підганяти»">
Якщо агент змінює тест, щоб той пройшов, перевірка втрачає сенс. Скажи прямо: «тести не змінюй, змінюй код». Для критичних тек можна заборонити редагування хуком.
</Callout>

## Рев'ю без упередження

Сесія, що писала код, «вірить» своїм міркуванням. Незалежний погляд знаходить більше:

| Спосіб | Як |
| --- | --- |
| `/code-review` | рев'ю diff у свіжому субагенті, який не бачив вашої розмови |
| Субагент-рев'юер | `.claude/agents/reviewer.md` з `tools: Read, Grep, Glob` — може лише читати |
| Рев'ю проти spec | «Звір diff із SPEC.md, кожна вимога реалізована й має тест, стиль пропускай» |
| Окрема сесія | нова сесія або worktree читає PR як незнайомий код |

<Callout type="pro" title="Скажи «пропусти стиль»">
Рев'юер, якого попросили знайти проблеми, завжди щось знайде. Якщо виправляти все, з'являться зайві абстракції й тести для неможливих випадків. Проси звіт лише про те, що впливає на коректність.
</Callout>

## Ворота якості і Definition of Done

Те, що має виконуватися **завжди**, не пиши лише в промпт чи <Term id="claude-md" />: модель може вирішити, що правило тут не діє. Для гарантій є:

- <Term id="hook" />: наприклад, `Stop`-хук, що не дає завершити, поки тести червоні;
- <Term id="ci" />: тести, lint, перевірка безпеки на кожен <Term id="pr" />;
- <Term id="definition-of-done" />: спільний чекліст команди.
