<TLDR>
- <Term id="streaming" /> віддає відповідь шматочками: користувач бачить текст одразу, а не через хвилину.
- Для довгих відповідей і великого <Term id="max-tokens" /> streaming обов'язковий — інакше впрешся в HTTP-таймаут.
- У TypeScript: `client.messages.stream(...)`, текст — через подію `"text"`, повний результат — `await stream.finalMessage()`.
</TLDR>

## Навіщо streaming

Звичайний запит повертає відповідь, лише коли модель дописала її повністю. Для короткої відповіді це секунда, для звіту на кілька тисяч слів — хвилина й більше тиші.

Streaming вирішує дві проблеми:

1. **UX** — текст друкується по мірі генерації, як у чаті Claude.
2. **Таймаути** — довгий неперервний запит може обірватись, а потік тримає з'єднання живим. SDK навіть вимагає streaming для дуже великих `max_tokens`.

## Як це виглядає в коді

```ts
const stream = client.messages.stream({
  model: "claude-opus-5-5",
  max_tokens: 64000,
  messages: [{ role: "user", content: "Напиши детальний звіт за листопад" }],
});

stream.on("text", delta => process.stdout.write(delta)); // шматочки тексту

const message = await stream.finalMessage(); // повна відповідь + usage
console.log("\n", message.stop_reason, message.usage.output_tokens);
```

| Що | Навіщо |
| --- | --- |
| `messages.stream()` | відкриває потік замість одного великого запиту |
| `on("text", …)` | отримуєш лише новий шматок тексту |
| `finalMessage()` | чекаєш завершення й отримуєш звичайний об'єкт відповіді |

<Callout type="tip" title="Не винаходь велосипед">
Не обгортай події потоку в `new Promise(...)` власноруч — `finalMessage()` уже обробляє завершення, помилки й скасування.
</Callout>

## Коли що використовувати

<DoDont
  dont={["Звичайний create з max_tokens: 64000 для довгого звіту", "Чекати повну відповідь у чат-інтерфейсі", "Власний парсер подій SSE поверх fetch"]}
  doThis={["messages.stream + finalMessage для довгих відповідей", "Показувати текст по мірі генерації", "Готові помічники SDK: on(\"text\"), finalMessage()"]}
/>

Короткі службові виклики (класифікація, витяг пари полів) можна робити звичайним `create` — там streaming нічого не дає.

## Потік і бекенд

У вебзастосунку ланцюжок такий: браузер ↔ твій сервер ↔ Claude. Сервер відкриває потік до API і пересилає шматки браузеру (наприклад, через `ReadableStream` у route handler). Ключ при цьому так само лишається на сервері.
