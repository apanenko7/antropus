## 1. Prompt caching

Якщо кожен запит починається з однакової довгої частини (інструкції, документація, приклади), API може закешувати цей **префікс** — повторне читання значно дешевше й швидше.

```ts
const res = await client.messages.create({
  model: "claude-opus-5-5",
  max_tokens: 1024,
  cache_control: { type: "ephemeral" }, // кешує останній придатний блок
  system: LONG_STABLE_INSTRUCTIONS,
  messages: [{ role: "user", content: review }],
});
console.log(res.usage.cache_read_input_tokens);
```

## 2. Batches API

Коли відповідь не потрібна миттєво (нічна обробка, звіти, розмітка даних), відправ запити пакетом: `client.messages.batches.create(...)`. Ціна — **половина** звичайної, результати забираєш пізніше за `custom_id` (порядок не гарантовано).

## 3. Effort і модель

- `output_config: { effort: "low" }` — менше міркувань і токенів для простих задач. На Opus 5.5 за замовчуванням `medium`, для складного коду піднімай до `high`.
- Haiku 5.5 — для класифікації, витягу полів, коротких відповідей; Opus — коли важлива якість.
- Перш ніж будувати складну схему «дешева модель → дорога», спробуй потужнішу модель з нижчим effort: часто це і дешевше, і якісніше.

<Callout type="pro" title="Рахуй вартість задачі">
Дешевий запит, після якого треба три повтори чи ручне виправлення, насправді дорожчий. Порівнюй варіанти на реальних прикладах (див. модуль «Оцінка та evals»).
</Callout>

## 4. Менше токенів на вході й виході

- Не шли зайвого: обрізай логи, передавай лише потрібні фрагменти документів.
- Обмежуй довжину відповіді в промпті («до 3 речень»), а `max_tokens` став із запасом — він лише стеля.
- Для довгих діалогів не тягни всю історію вічно: підсумовуй або починай нову розмову.
