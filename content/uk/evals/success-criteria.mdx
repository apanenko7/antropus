<TLDR>
- Поки не визначив, що таке «добре», неможливо сказати, чи промпт став кращим.
- Хороші <Term id="success-criteria">критерії успіху</Term> конкретні, вимірювані, досяжні й доречні для задачі.
- Зазвичай потрібно кілька вимірів одночасно: точність, тон, безпека, швидкість, вартість.
</TLDR>

## Навіщо критерії

Без критеріїв покращення промпту перетворюється на смакування: «здається, так краще». З критеріями ти отримуєш цифру, яку можна порівняти до і після зміни.

Аналогія: ти не наймаєш працівника з вимогою «працювати добре». Ти кажеш, що саме має бути зроблено, до якого терміну і як ти зрозумієш, що все вийшло.

## Виміри, про які легко забути

Майже завжди задача має кілька вимірів одразу. Документація Anthropic наводить такі:

| Вимір | Питання | Приклад метрики |
| --- | --- | --- |
| Точність задачі | Чи правильно виконано, зокрема на складних прикладах? | % правильних міток |
| Послідовність | Схожі питання → схожі відповіді? | Схожість відповідей на перефразовані питання |
| Релевантність | Відповідає на питання, логічно викладено? | Оцінка судді 1–5 |
| Тон і стиль | Підходить аудиторії? | Оцінка ввічливості 1–5 |
| Приватність | Не розкриває чужі дані? | 0 витоків на N прикладів |
| Використання контексту | Спирається на надані документи? | % відповідей із правильною цитатою |
| Швидкість | Відповідає вчасно? | 95% до 3 секунд |
| Вартість | Вкладається в бюджет? | ≤ X грн на 1000 запитів |

## Приклади для різних задач

| Задача | Критерії |
| --- | --- |
| Класифікація звернень | ≥ 92% правильних міток на 300 прикладах; 100% звернень про повернення коштів — до людини |
| Підсумок зустрічі | Усі рішення й відповідальні присутні; до 150 слів; 0 вигаданих пунктів |
| Переклад інструкцій | Оцінка мовного експерта ≥ 4 з 5; усі назви кнопок збігаються з інтерфейсом |
| Генерація коду | Усі тести проходять; лінтер без помилок; без нових залежностей |
