<TLDR>
- Агент виконує команди з твоїми правами, тож давай йому мінімум потрібного (<Term id="least-privilege" />).
- Шари захисту: <Term id="permissions">дозволи</Term> → <Term id="sandbox">пісочниця</Term> → <Term id="devcontainer">контейнер</Term> чи VM для повністю автономної роботи.
- Будь-які чужі дані (сайти, файли, issue, MCP) можуть містити <Term id="prompt-injection" />. Секрети не повинні бути там, де агент може їх прочитати.
</TLDR>

## Чому агент — нова поверхня атаки

Чат-бот лише відповідає текстом. <Term id="agent">Агент</Term> **діє**: запускає команди, ходить у мережу, змінює файли — і все це з правами твого користувача. Помилка моделі чи зловмисний текст у даних перетворюються на реальні дії.

Тому безпека агента будується шарами: якщо один не спрацював, спрацює наступний.

## Шари захисту в Claude Code

| Шар | Що робить | Як увімкнути |
| --- | --- | --- |
| Дозволи | Небезпечні дії потребують твого «так»; deny-правила забороняють назавжди | `/permissions`, `permissions.deny` у <Term id="settings-json" /> |
| Межа робочої папки | Файлові інструменти питають перед читанням чи записом поза папкою проєкту | За замовчуванням у ручному режимі |
| Пісочниця | Межа на рівні ОС для Bash-команд: запис лише в робочу папку, мережа лише на дозволені домени | `/sandbox` або `sandbox.enabled: true` |
| Контейнер / VM | Ізолює весь процес Claude Code від основної системи | <Term id="devcontainer" />, віртуальна машина |

<Callout type="warn" title="Пісочниця не всюди">
Вбудована пісочниця працює на macOS, Linux і WSL2. На «чистому» Windows команди виконуються без неї — там для ізоляції використовуй WSL2 або контейнер.
</Callout>

## Prompt injection

**Ін'єкція промпту** — коли в даних, які читає агент, заховані інструкції для нього: у README, на вебсторінці, в описі issue, у відповіді <Term id="mcp" />-сервера.

<Demo script={injectionDemo} />

Як зменшити ризик:

- переглядай команди, які агент пропонує, особливо з мережею (`curl`, `wget`);
- не «згодовуй» агенту неперевірений контент без потреби;
- для роботи з чужими сайтами й скриптами — пісочниця або VM;
- підключай MCP-сервери лише від тих, кому довіряєш, або пиши власні.

Приклад правил у `.claude/settings.json`, які забороняють читати секрети й запускати мережеві завантажувачі:

```json
{
  "permissions": {
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)", "Bash(curl *)", "Bash(wget *)"]
  }
}
```

## Автономні режими — з головою

Режими, у яких агент працює без підтвердження кожного кроку, економлять час, але переносять відповідальність на інші шари. Повністю вимкнений контроль дозволів (`--dangerously-skip-permissions`) доречний **лише** в ізольованому середовищі: контейнері чи VM без доступу до важливих даних і облікових записів.

<Callout type="pro" title="Правило великого пальця">
Що більше в агента автономії, то сильнішою має бути ізоляція. Автономія + доступ до мережі + доступ до секретів = найризикованіша комбінація.
</Callout>
