<TLDR>
- <Term id="claude-md" /> — markdown-файл, який Claude Code читає на старті **кожної** сесії: постійні інструкції проєкту.
- Пиши лише те, чого агент не дізнається з коду: команди перевірки, неочевидні домовленості, підводні камені.
- Коротко: до 200 рядків. Почни з `/init`, а потім викреслюй зайве.
</TLDR>

## Навіщо він

Кожна сесія стартує з чистим контекстом. Без CLAUDE.md ти щоразу пояснюєш одне й те саме: «тести запускаються так», «помилки кидаємо через наш хелпер». CLAUDE.md — це <Term id="memory" />, яку ти пишеш сам один раз.

<Callout type="tip" title="Кожен рядок коштує уваги">
Файл завантажується в кожну задачу, навіть не пов'язану з ним. Тому кожен зайвий рядок трохи розмиває увагу агента. Чим коротше й конкретніше, тим краще він виконує.
</Callout>

Формулюй так, щоб можна було перевірити:

| Замість | Пиши |
| --- | --- |
| «Форматуй код правильно» | «Відступ 2 пробіли» |
| «Тестуй зміни» | «Перед комітом запускай `npm test`» |
| «Тримай файли впорядкованими» | «API-хендлери лежать у `src/api/handlers/`» |

Добрий CLAUDE.md виглядає приблизно так:

```markdown
# Commands
- Install: pnpm install
- One test: pnpm vitest run path/to/file.test.ts
- Typecheck: pnpm tsc --noEmit

# Conventions
- Errors via helpers in src/lib/errors.ts, never throw raw strings
- src/legacy/ is live, but don't copy its patterns

# Gotchas
- Integration tests need DATABASE_URL, see .env.example
```

## Де він лежить

| Файл | Для чого | Хто бачить |
| --- | --- | --- |
| `./CLAUDE.md` або `./.claude/CLAUDE.md` | правила проєкту | уся команда через git |
| `./CLAUDE.local.md` | твої особисті нотатки до проєкту (додай у `.gitignore`) | лише ти |
| `~/.claude/CLAUDE.md` | твої вподобання для всіх проєктів | лише ти |

Усі знайдені файли **об'єднуються**, а не перекривають один одного. CLAUDE.md у підпапках підвантажуються, коли агент працює з файлами в них. Інші файли можна підключити імпортом: рядок `@README.md` в CLAUDE.md додасть README в контекст.

<Callout type="warn" title="Це підказка, а не замок">
CLAUDE.md — контекст, а не жорстке правило. «Ніколи не роби push» працює майже завжди, але не гарантовано. Те, що не має винятків, закривай через <Term id="permissions">дозволи</Term> (deny) або <Term id="hook">хуки</Term>.
</Callout>
