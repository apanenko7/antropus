<TLDR>
- <Term id="permissions">Дозволи</Term> вирішують, що агент робить сам, а про що питає. `Shift+Tab` перемикає режими просто в сесії.
- <Term id="plan-mode" /> — агент досліджує й пише план, але не змінює файли, доки ти не погодиш план.
- `Esc` зупиняє агента, а `Esc` двічі (або `/rewind`) відкочує код і розмову до попереднього кроку.
</TLDR>

## Запит дозволу

Коли агент хоче зробити щось потенційно небезпечне, він питає. Читання файлів у проєкті запиту не потребує, а от редагування й більшість команд — потребують (у ручному режимі).

| Варіант відповіді | Що станеться |
| --- | --- |
| **Yes** | дозволити один раз |
| **Yes, and don't ask again for…** | дозволити такі команди й надалі в цьому репозиторії |
| **No** | відмовити; `Esc` діє так само |

Для команд «don't ask again» зберігає правило в `.claude/settings.local.json`, тож воно діятиме й у наступних сесіях. Дозвіл на редагування файлів діє лише до кінця сесії.

## Режими дозволів

`Shift+Tab` по колу перемикає режими. Поточний видно під полем вводу.

| Режим | Що робить без питань |
| --- | --- |
| **Manual** (`default`) | лише читає; на зміни й команди питає |
| **Edit automatically** (`acceptEdits`) | ще й редагує файли та виконує прості файлові команди (`mkdir`, `mv`…) |
| **Plan** (`plan`) | лише досліджує й пише план, файли не чіпає |
| **<Term id="auto-mode">Auto</Term>** (`auto`) | майже все, а ризиковані дії блокує фоновий класифікатор |

Цикл `Shift+Tab`: Manual → Edit automatically → Plan, а далі додаткові режими, якщо вони доступні. У нових версіях Claude Code сесія в терміналі стартує одразу в auto mode.

<Callout type="warn" title="Bypass permissions — лише в пісочниці">
Режим `bypassPermissions` (`--dangerously-skip-permissions`) вимикає всі перевірки. Він для ізольованих контейнерів і віртуальних машин, а не для твого ноутбука з робочими ключами.
</Callout>

## Plan mode: спершу план, потім код

Для великої зміни перемкнись у <Term id="plan-mode" /> (`Shift+Tab` або `/plan` перед задачею). Агент прочитає код, поставить питання й запропонує план. Коли план готовий, Claude спитає, як продовжити:

- **Yes, and use auto mode** — погодити й працювати в auto mode;
- **Yes, manually approve edits** — погодити, але підтверджувати кожну правку;
- **No, keep planning** — лишитися в плануванні й пояснити, що змінити.

`Ctrl+G` відкриває план у текстовому редакторі, щоб відредагувати його перед стартом.

## Правила в settings.json

Щоб не тиснути «Yes» на `npm test` щоразу, додай правила у <Term id="settings-json" />:

```json
{
  "permissions": {
    "allow": ["Bash(npm run *)", "Bash(git commit *)"],
    "deny": ["Bash(git push *)", "Read(./.env)"]
  }
}
```

Правила перевіряються в порядку **deny → ask → allow**: deny завжди перемагає, навіть якщо є вужче allow. `.claude/settings.json` комітиться для всієї команди, `.claude/settings.local.json` — лише для тебе, `~/.claude/settings.json` — для всіх твоїх проєктів. Керувати правилами в сесії можна командою `/permissions`.

## Зупинити й відкотити

- **`Esc`** — зупиняє агента посеред дії. Зроблене до цього моменту лишається, і можна одразу скерувати інакше.
- **Повідомлення під час роботи** — просто напиши й натисни Enter: агент прочитає його після поточного кроку.
- **`Esc` двічі на порожньому полі або `/rewind`** — меню <Term id="checkpoint">контрольних точок</Term>: відкотити код, розмову або обидва до одного з попередніх повідомлень.

<Callout type="tip" title="Чого rewind не поверне">
Контрольні точки покривають файли, які агент змінив своїми інструментами редагування. Зміни через Bash-команди, а також дії назовні (база даних, API, деплой) не відкочуються. Тому <Term id="git" /> усе одно потрібен.
</Callout>
